# راهنمای نصب بوفه روی سرور

این بسته **self-contained** است: روی سرور نیازی به نصب .NET نیست (به‌جز روش IIS که پایین گفته شده).
سرور: Windows Server 2016 به بالا یا Windows 10/11، نسخه‌ی ۶۴ بیتی.

## ۱. کپی فایل‌ها

محتوای پوشه را در یک مسیر ثابت روی سرور بگذارید، مثلاً `C:\Apps\OfficeBuffet`.

> داده‌ها در پوشه‌ی `App_Data` کنار برنامه ساخته می‌شوند (دیتابیس + کلیدهای ورود).
> کاربری که برنامه را اجرا می‌کند باید روی این پوشه **اجازه‌ی نوشتن** داشته باشد.

## ۲. اجرا — یکی از این سه روش

### روش الف) سرویس ویندوز (پیشنهادی)
با Windows شروع می‌شود و اگر به هر دلیلی بسته شد خودکار دوباره بالا می‌آید.
در PowerShell **Run as Administrator**:

```powershell
cd C:\Apps\OfficeBuffet
powershell -ExecutionPolicy Bypass -File .\install-service.ps1
```

پیش‌فرض روی پورت `5080` اجرا می‌شود و پورت در فایروال باز می‌شود. برای پورت دیگر: `-Port 80`.
حذف سرویس: `uninstall-service.ps1` (داده‌ها پاک نمی‌شوند).

### روش ب) IIS
۱. **ASP.NET Core 10 Hosting Bundle** را روی سرور نصب کنید (از سایت مایکروسافت) و IIS را ری‌استارت کنید.
۲. یک Site یا Application جدید با مسیر `C:\Apps\OfficeBuffet` بسازید. فایل `web.config` آماده است.
۳. در Application Pool: `.NET CLR version = No Managed Code`.
۴. به هویت Application Pool (مثلاً `IIS AppPool\OfficeBuffet`) اجازه‌ی **Modify** روی پوشه‌ی برنامه بدهید (برای ساخت `App_Data`).

### روش ج) اجرای ساده (برای تست)
`OfficeBuffet.exe` را اجرا کنید. تا پنجره باز است برنامه روی `http://IP-سرور:5080` در دسترس است.

## ۳. اولین ورود

آدرس را در مرورگر باز کنید و از «ورود مسئول بوفه» حساب مسئول را بسازید
(فرم ساخت حساب فقط وقتی دیده می‌شود که هنوز هیچ حسابی وجود ندارد — پس **بلافاصله بعد از نصب** این کار را انجام دهید).
بعد در «افراد» برای هر نفر نام و کد ملی را وارد کنید.

### انتقال داده‌های فعلی (اختیاری)
اگر می‌خواهید اطلاعاتی که روی سیستم فعلی ثبت شده منتقل شود: برنامه را روی هر دو سیستم ببندید و
پوشه‌ی `App_Data` (فایل `officebuffet.db` + پوشه‌ی `keys`) را از سیستم فعلی به کنار برنامه روی سرور کپی کنید.

## ۴. HTTPS (برای «نصب» به‌صورت اپ روی گوشی)

برنامه روی `http` کامل کار می‌کند، اما گوشی‌ها گزینه‌ی **Add to Home Screen / نصب اپ** را فقط روی `https` نشان می‌دهند.
- با IIS: یک گواهی SSL (گواهی داخلی شرکت یا گواهی دامنه) روی Binding سایت تنظیم کنید.
- با سرویس ویندوز: گواهی را به `appsettings.json` اضافه کنید:

```json
"Kestrel": {
  "Endpoints": {
    "Https": { "Url": "https://0.0.0.0:443",
      "Certificate": { "Path": "C:\\Apps\\cert.pfx", "Password": "..." } }
  }
}
```

نکته: اگر از گواهی داخلی (self-signed یا CA داخلی) استفاده کنید، باید روی گوشی‌ها هم مورد اعتماد باشد.

### اعلان درخواست‌ها روی گوشی مسئول
وقتی کارمندی درخواست می‌فرستد (مثلاً «یک قهوه»)، گوشی مسئول اعلان می‌گیرد؛ حتی اگر برنامه بسته باشد. شرایط:
- برنامه با **https** باز شود (روی `http` مرورگرها اجازه‌ی اعلان نمی‌دهند).
- **سرور به اینترنت دسترسی خروجی** داشته باشد تا اعلان را به سرویس گوگل/اپل/موزیلا بفرستد:
  `fcm.googleapis.com` (اندروید/کروم)، `*.push.apple.com` (آیفون)، `*.push.services.mozilla.com` (فایرفاکس).
  اگر سرور فقط از طریق پروکسی به اینترنت وصل می‌شود، پروکسی را در تنظیمات سیستم (WinHTTP) تنظیم کنید.
- مسئول در صفحه‌ی «درخواست‌ها» دکمه‌ی **فعال‌سازی اعلان** را بزند و اجازه بدهد؛ بعد «ارسال اعلان آزمایشی» را امتحان کند.
- آیفون: iOS 16.4 به بالا، و برنامه باید اول با «Add to Home Screen» نصب و از همان آیکون باز شود.

بدون این شرایط هم، تا وقتی برنامه روی گوشی یا کامپیوتر مسئول باز است، درخواست جدید با صدا، پیام و عدد روی تب «درخواست‌ها» اطلاع داده می‌شود.

## ۵. بکاپ

پوشه‌ی `App_Data` را به‌طور منظم کپی کنید (بهتر است وقتی سرویس متوقف است، یا از نسخه‌ی کپی‌شده‌ی شبانه).
- `officebuffet.db` (یا `officebite.db` در نصب‌های قدیمی‌تر) — همه‌ی اطلاعات
- `keys` — کلیدهای ورود؛ اگر گم شود فقط همه باید دوباره وارد شوند، داده‌ای از دست نمی‌رود.
- `vapid.json` — کلید اعلان‌ها؛ اگر گم شود فقط باید اعلان را روی گوشی مسئول دوباره فعال کرد.

## ۶. به‌روزرسانی به نسخه‌ی جدید

۱. سرویس (یا سایت IIS) را متوقف کنید. ۲. از `App_Data` بکاپ بگیرید.
۳. فایل‌های جدید را روی پوشه‌ی برنامه کپی کنید (**پوشه‌ی `App_Data` را پاک نکنید**).
۴. سرویس را دوباره اجرا کنید. تغییرات دیتابیس خودکار اعمال می‌شود.

### به‌روزرسانی از نسخه‌ای که هنوز اسمش OfficeBite بود
- فایل اجرایی حالا `OfficeBuffet.exe` است. فایل‌های قدیمی `OfficeBite.*` را می‌توانید از پوشه پاک کنید (به `App_Data` دست نزنید).
- **سرویس ویندوز:** `install-service.ps1` جدید را یک بار اجرا کنید؛ سرویس قدیمی `OfficeBite` و قانون فایروالش را خودش حذف و سرویس `OfficeBuffet` را نصب می‌کند.
- **IIS:** `web.config` جدید خودش به `OfficeBuffet.exe` اشاره می‌کند؛ فقط سایت را دوباره Start کنید.
- دیتابیس قبلی (`App_Data\officebite.db`) با همین اسم پیدا و استفاده می‌شود؛ نیازی به تغییر اسم نیست. ورود کاربران و اعلان‌ها هم قطع نمی‌شود.
