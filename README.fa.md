بوفه جای دفترچه‌ی کاغذی آبدارخانه را می‌گیرد:
- مسئول بوفه ثبت می‌کند هر همکار چه چیزی برداشته است.
- همکاران از پشت میزشان درخواست می‌فرستند، مثلاً «یک قهوه، اتاق ۲۰۳».
- هر کس هر وقت بخواهد مصرف و مانده‌ی حساب خودش را می‌بیند.
- آخر ماه، حساب‌ها «تا یک تاریخ» تسویه می‌شوند و سابقه‌ی کامل و غیرقابل‌دستکاری باقی می‌ماند.

رابط کاربری فارسی و راست‌چین است و تاریخ‌ها شمسی و مبالغ به تومان هستند. ورود همکاران با کد ملی است و رقم کنترل کد ملی هم بررسی می‌شود. کل برنامه روی سرور خود شرکت و داخل شبکه‌ی داخلی اجرا می‌شود.

## امکانات

### برای همکاران

- **ورود فقط با کد ملی:** رمزی لازم نیست. یک بار وارد شوید و روی همان دستگاه وارد می‌مانید.
- **لیست قیمت:** همه‌ی اقلام با قیمت روز. اقلام رایگان مشخص‌اند.
- **درخواست از پشت میز:** اقلام را انتخاب کنید و توضیح بنویسید تا گوشی مسئول بوفه زنگ بخورد.
- **دکمه‌ی «👋 یه تلنگر بزن!»:** اگر درخواست طول کشید، دوباره به مسئول خبر بدهید. حداکثر دو بار می‌شود و بین هر دو بار دست‌کم دو دقیقه فاصله لازم است. بعد از آن برنامه پیشنهاد می‌کند حضوری سر بزنید.
- **اعلان جواب درخواست:** «☕ درخواستت دیده شد، تا دقایقی دیگر آماده می‌شود» یا «✋ رد شد» همراه با دلیل.
- **فقط حساب خودش:** هر کس فقط سفارش‌ها، پرداخت‌ها، تسویه‌ها و مانده‌ی خودش را می‌بیند.

### برای مسئول بوفه

- **ثبت سفارش سریع:** روی گوشی یا کامپیوتر، شخص را انتخاب کنید، اقلام را بزنید و تمام.
- **ثبت برای روزهای قبل:** سفارش‌هایی که روی کاغذ نوشته شده‌اند را می‌شود بعداً با تاریخ همان روز وارد کرد، تا ۶۰ روز قبل. زمان واقعی ثبت هم کنارشان می‌ماند.
- **صندوق درخواست‌ها:** دو تب «در انتظار» و «رسیدگی‌شده» دارد.
  - **ثبت:** درخواست با قیمت روز به سفارش تبدیل می‌شود.
  - **رد:** دلیل را می‌پرسد تا همکار ببیند.
- **هشدار:** اعلان روی گوشی مسئول حتی با برنامه‌ی بسته. وقتی برنامه باز است، زنگ مخصوص و ویبره هم دارد.
- **پرداخت و تسویه:** ثبت پرداخت، دیدن مانده‌ی همه، و تسویه‌ی حساب هر نفر «تا یک تاریخ»، مثلاً تا آخر ماه.
- **گزارش‌ها:** امروز، دیروز، این هفته، این ماه، ماه قبل یا همه؛ برای یک نفر یا همه.
- **ورود از اکسل یا CSV** برای کالاها و افراد، با انتخاب ستون‌ها و پیش‌نمایش:
  - هیچ چیز تکراری ثبت نمی‌شود. «ي/ك» عربی و «ی/ک» فارسی یکی حساب می‌شوند.
  - قیمت کالاهای موجود به‌روز می‌شود.
  - کد ملی‌های نامعتبر یا تکراری در یک لیست نشان داده می‌شوند.
  - صفرهای اول کد ملی که Excel حذف کرده دوباره اضافه می‌شود.
- چند حساب مسئول، تغییر رمز، و تم روشن و تیره.

### قابل اعتماد

- **هیچ چیز پاک نمی‌شود:** ثبت اشتباه با ذکر دلیل «ابطال» می‌شود. اینکه چه کسی، کِی و چه چیزی را ابطال کرد در سابقه می‌ماند.
- **قیمت لحظه‌ی سفارش ثابت می‌ماند:** تغییر قیمت بعدی حساب‌های قبلی را عوض نمی‌کند.
- **داده‌ها نزد خودتان:** همه‌چیز در یک فایل SQLite است و به هیچ سرویس بیرونی نیاز نیست. تنها استثنا اعلان‌ها هستند که از سرویس اعلان مرورگرها می‌گذرند.
- **سبک:** یک PWA بدون فریم‌ورک که روی گوشی نصب می‌شود. فونت وزیرمتن داخل خود برنامه است.

## فناوری‌ها

| بخش | فناوری |
|---|---|
| سرور | ASP.NET Core 10 (Minimal API) |
| داده | EF Core 10 + SQLite، با Migration (خودکار موقع اجرا) |
| احراز هویت | کوکی ماندگار، هش رمز PBKDF2، محدودیت تعداد تلاش ورود |
| رابط کاربری | HTML/CSS/JS ساده بدون فریم‌ورک و بدون مرحله‌ی build، با Service Worker و Manifest |
| اعلان | Web Push استاندارد (RFC 8291 و RFC 8292)، بدون پکیج جانبی |
| ورود اطلاعات | خواننده‌ی داخلی ‎.xlsx و CSV (UTF-8 یا Windows-1256) |
| میزبانی | سرویس ویندوز، IIS، یا هر سیستمی که .NET 10 را اجرا کند |

## شروع سریع

**فقط می‌خواهید اجرا کنید؟** فایل `OfficeBuffet-<نسخه>-win-x64.zip` را از [آخرین نسخه (Releases)](https://github.com/Mohamadkhadem/OfficeBuffet/releases/latest) دانلود و از حالت فشرده خارج کنید و `OfficeBuffet.exe` را اجرا کنید. نیازی به نصب .NET نیست. برای اجرا به‌صورت سرویس، بخش [نصب روی سرور](#نصب-روی-سرور) را ببینید.

**از روی سورس**، با [.NET 10 SDK](https://dotnet.microsoft.com/download):

```bash
git clone https://github.com/Mohamadkhadem/OfficeBuffet.git
cd OfficeBuffet
dotnet run
```

بعد `http://localhost:5080` را باز کنید. دفعه‌ی اول:

1. از **«ورود مسئول بوفه»** اولین حساب مسئول را بسازید. این فرم فقط تا وقتی هیچ حسابی وجود ندارد دیده می‌شود، پس بلافاصله بعد از نصب این کار را انجام دهید.
2. در **«کالاها»** اقلام و قیمت‌ها را وارد کنید و در **«افراد»** همکاران را با کد ملی. هر دو را می‌شود از اکسل هم وارد کرد.
3. همکاران همین آدرس را روی گوشی باز می‌کنند و با کد ملی وارد می‌شوند.

برنامه روی همه‌ی کارت‌های شبکه گوش می‌دهد، پس از گوشی‌های داخل شبکه با `http://IP-سرور:5080` باز می‌شود. ممکن است لازم باشد پورت 5080 را در فایروال باز کنید.

## تنظیمات

از `appsettings.json`، متغیر محیطی یا آرگومان خط فرمان (`--Key=value`):

| کلید | پیش‌فرض | کاربرد |
|---|---|---|
| `Urls` | `http://0.0.0.0:5080` | آدرس و پورت، مثلاً `http://0.0.0.0:80;https://0.0.0.0:443` |
| `DbPath` | `App_Data/officebuffet.db` | فایل دیتابیس. کلیدهای ورود و کلید اعلان کنار همین فایل نگه داشته می‌شوند. |
| `Push:Subject` | `mailto:officebuffet@example.com` | آدرس تماسی که برای سرویس‌های اعلان فرستاده می‌شود. یک آدرس واقعی بگذارید. |
| `Kestrel:Certificates:Default:Path` و `:Password` | – | گواهی https، وقتی خود برنامه https را سرو می‌کند |

اگر فایل `certs/kestrel.json` کنار برنامه باشد (که `tools/new-certificate.ps1` می‌سازد)، خودکار خوانده می‌شود.

## نصب روی سرور

نسخه‌ی Release مستقل است و روی سرور نیازی به نصب .NET ندارد، مگر برای IIS:

```bash
dotnet publish -c Release -r win-x64 --self-contained -o publish/OfficeBuffet
```

پوشه را روی سرور کپی کنید و یکی از این روش‌ها را انتخاب کنید:

- **سرویس ویندوز (پیشنهادی):** `install-service.ps1` را با Run as Administrator اجرا کنید. سرویس با ویندوز بالا می‌آید، اگر بسته شود دوباره اجرا می‌شود و پورتش در فایروال باز می‌شود.
- **IIS:** ASP.NET Core 10 Hosting Bundle را نصب کنید و یک سایت با مسیر همین پوشه بسازید (`web.config` آماده است). Application Pool را روی *No Managed Code* بگذارید.
- **اجرای ساده:** فقط `OfficeBuffet.exe` را اجرا کنید.

راهنمای کامل، شامل به‌روزرسانی، انتقال داده‌های فعلی و بکاپ، در [`deploy/DEPLOY.md`](deploy/DEPLOY.md) است. پوشه‌های `App_Data` و `certs` هیچ‌وقت در خروجی build قرار نمی‌گیرند، پس به‌روزرسانی داده‌ها و کلیدهای سرور را بازنویسی نمی‌کند.

## https، نصب روی گوشی و اعلان‌ها

همه‌چیز روی `http` ساده کار می‌کند. مرورگرها فقط این دو امکان را روی `https` (یا `localhost`) می‌دهند:
- نصب به‌صورت اپ روی صفحه‌ی اصلی؛
- اعلان (Push).

روی شبکه‌ی داخلی بدون دامنه‌ی عمومی، دو راه دارید:

- برنامه را پشت IIS یا یک reverse proxy با گواهی‌ای بگذارید که دستگاه‌ها به آن اعتماد دارند.
- یا `tools/new-certificate.ps1` را اجرا کنید:
  - یک CA کوچک خصوصی و یک گواهی سرور برای IPهای سرور می‌سازد. کلید خصوصی CA بلافاصله بعد از امضا پاک می‌شود.
  - فایل `certs/officebuffet-ca.cer` را یک بار روی هر گوشی نصب کنید.
  - در آیفون، علاوه بر نصب، باید در *Settings ← General ← About ← Certificate Trust Settings* هم آن را فعال کنید.

برای اعلان‌ها این شرایط هم لازم است:

- سرور باید به اینترنت دسترسی خروجی داشته باشد تا به سرویس‌های اعلان برسد: `fcm.googleapis.com` و `*.push.apple.com` و `*.push.services.mozilla.com`.
- آیفون: iOS 16.4 به بالا، و برنامه باید از آیکون صفحه‌ی اصلی باز شود.
- هر نفر اعلان را یک بار روی دستگاهش روشن می‌کند:
  - مسئول، برای درخواست‌های جدید و تلنگرها؛
  - همکاران، برای جواب درخواست‌هایشان.

بدون اعلان هم، وقتی برنامه باز است، درخواست‌ها و جواب‌ها با صدا و پیام روی صفحه اطلاع داده می‌شوند.

## داده‌ها و بکاپ

همه‌چیز در پوشه‌ی داده است (پیش‌فرض `App_Data`):

| فایل | محتوا | اگر گم شود |
|---|---|---|
| `officebuffet.db` | همه‌ی اطلاعات | از بکاپ برگردانید |
| `keys/` | کلیدهای رمزنگاری کوکی ورود | همه باید دوباره وارد شوند |
| `vapid.json` | کلید اعلان‌ها | اعلان باید روی دستگاه‌ها دوباره روشن شود |

برای بکاپ، وقتی برنامه خاموش است این پوشه را کپی کنید. نصب‌های قبل از تغییر اسم پروژه همان `officebite.db` قبلی را خودکار استفاده می‌کنند.

## قواعد حساب‌وکتاب

- **مانده** برابر است با مصرف منهای پرداخت، بعد از آخرین تسویه. عدد مثبت یعنی بدهکار.
- **تسویه تا تاریخ:**
  - همه‌ی سفارش‌ها و پرداخت‌های آن شخص تا پایان آن روز شمسی بسته می‌شوند، فارغ از اینکه چقدر پرداخت کرده.
  - مبلغی که صفر شد برای سابقه ذخیره می‌شود.
  - گزارش مصرف دست نمی‌خورد.
- **ابطال به‌جای حذف:** سفارش، پرداخت و تسویه فقط با ذکر دلیل ابطال می‌شوند. کالا یا شخصی که سابقه دارد غیرفعال می‌شود، نه حذف.
- **درخواست‌ها:**
  - درخواست تا وقتی مسئول ثبتش نکرده در حساب کسی نمی‌آید.
  - هر نفر حداکثر ۳ درخواست در انتظار دارد.
  - تا قبل از رسیدگی، درخواست را می‌شود لغو کرد.

## نکات امنیتی

بوفه برای **شبکه‌ی داخلی و قابل اعتماد شرکت** طراحی شده است، نه برای اینترنت عمومی.

- **ورود با کد ملی:** همکاران فقط با کد ملی و بدون رمز وارد می‌شوند. پس هر کس کد ملی دیگری را بداند می‌تواند ثبت‌های او را *ببیند*، ولی نمی‌تواند چیزی را تغییر دهد. غیرفعال کردن شخص یا تغییر کد ملی‌اش دسترسی او را فوراً قطع می‌کند.
- **رمز مسئول:** با PBKDF2-SHA256 و ۱۰۰٬۰۰۰ تکرار هش می‌شود. تعداد تلاش‌های ورود برای هر IP محدود است.
- **کوکی‌ها و دسترسی:** کوکی‌ها `HttpOnly` و `SameSite=Strict` هستند. همه‌ی مسیرهای داده نیاز به ورود دارند و فقط ورود و ساخت حساب اول عمومی است.
- **فایل‌های اکسل:** با محدودیت حجم، بدون پردازش DTD و با محافظت در برابر zip bomb خوانده می‌شوند.
- **فایل‌های خصوصی:** `App_Data/` و `certs/` را هرگز در مخزن قرار ندهید. هر دو در `.gitignore` هستند.

اگر آسیب‌پذیری پیدا کردید، لطفاً به‌جای issue عمومی، به نگهدارندگان پروژه خصوصی اطلاع دهید.

## توسعه

```bash
dotnet run                     # http://localhost:5080
dotnet build -c Release        # بررسی کامپایل
```

رابط کاربری مرحله‌ی build ندارد. فایل‌های `wwwroot/` را ویرایش و صفحه را رفرش کنید. اگر فایل‌هایی که در کش هستند را تغییر دادید، نسخه‌ی `CACHE` را در `wwwroot/sw.js` یکی بالا ببرید تا اپ‌های نصب‌شده تغییر را بگیرند.

برای تغییر ساختار دیتابیس، `Data/Models.cs` را تغییر دهید و یک Migration بسازید. Migration موقع اجرای بعدی خودکار اعمال می‌شود و داده‌ها حفظ می‌شوند:

```bash
dotnet tool restore
dotnet tool run dotnet-ef migrations add <نام> -o Data/Migrations
```

در Visual Studio، پروفایل `https` روی `https://localhost:7080` و `http://localhost:5080` اجرا می‌شود.

**انتشار نسخه‌ی جدید:**
1. `<Version>` را در `OfficeBuffet.csproj` بالا ببرید. این عدد در برنامه، در «تنظیمات ← درباره»، نشان داده می‌شود.
2. تغییرات را در [CHANGELOG.md](CHANGELOG.md) بنویسید.
3. commit را با `vX.Y.Z` تگ بزنید.
4. فایل zip مستقل را به Release در GitHub پیوست کنید.
